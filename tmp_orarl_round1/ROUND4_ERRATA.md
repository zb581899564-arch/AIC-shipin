## 勘误 1 — `free_axis_travel` 不是实测主体或裁剪框运动量

**round4 的说法**：把 10 个冻结来源组称为「高运动层」，并在 §0 Q2/Q3 中以
「高运动层不明显退化」「无法按运动分层回答」等措辞讨论运动强度。

**更正**：`clip.free_axis_travel` 表示**可用裁剪轴上的空间范围**，
**不是**实测的主体运动量，也**不是**裁剪框的运动量。
round4 自己已经发现它（0.4375–0.7630）与弱代理框自身 x 位移（中位 0.0956）**不是同一量**，
却没有据此收回「高运动层」的称呼，属于口径不一致。

**正确表述**：
- 本轮应称为**单一 `free_axis_travel` 层**，而不是「高运动层」；
- **运动分层结论记为 `NOT_COMPUTABLE`**；
- `free_axis_travel` 只作为**元数据**保留，**不用于分层**。

（round5 据此完全不再用 `free_axis_travel` 做任何分层。）

## 勘误 2 — 弱标签宽度不是「577/577 恰好等于最大合法宽度」

**round4 的说法**：§0 Q5 与 `crop_scale_stats.json` 称
「**恰好等于最大合法宽度的比例 = 1.000（577/577）**」。

**更正**：冻结入口在 534×300、9:16 下算出的合法宽度是 **168**，而标签使用的是 **169**，
比例为 `169/168 = 1.005952`。统计脚本把 `w >= 0.999` 计为 `frac_exactly_max_legal`，
因此该字段实际含义只是「**没有小于最大宽度约束**」，**不是**「恰好等于最大宽度」。

**正确表述**：
- 应写作「**0 条小于最大宽度约束**」或「宽度比恒为 1.005952（仅差一个取整像素）」；
- 「标签没有动态宽度信号」这一结论**可以保留**，因为 577 条宽度**完全相同**且只相差一个取整像素；
- 不应把 `frac_exactly_max_legal` 这个字段名当成字面结论引用。

## 勘误 3 — 仅比较 rate 字段不足以排除 VFR

**round4 的说法**：`mapping_report.json` 记录 `vfr_excluded = 0`，报告写作
「0 VFR」，容易读成「全部 820 个可用映射都已确认是 CFR」。

**更正**：对全部 820 个可用映射，只比较 `r_frame_rate == avg_frame_rate`
**不能充分排除 VFR**（可变帧率视频的两个 rate 字段完全可能写成同一个值）。

**正确表述**：
- 该统计应改写为「**0 个 rate-field mismatch**」；
- 真正的 CFR 证据只覆盖**本轮冻结的 10 个源视频**——主管已逐帧读取 PTS：
  10/10 的流与容器起始时间均为 0，相邻帧时间步长相对中位数的最大偏差 ≤1 微秒；
- 不得把「0 rate-field mismatch」推广为「820 条全部 CFR」。

## 勘误 4 — P2/P3 并非「未通过任何一项质量门槛」

**round4 的说法**：§0 Q2 写「**都没有通过。两条路线均未通过任何一项质量门槛。**」

**更正**：P2 与 P3 **各自通过了一项**（有效率 100%，即 1/6 项通过），
只是**总体门槛不通过**。

**正确表述**：「**P2、P3 各通过 1/6 项（有效率），总体门槛不通过。**」

---

## 勘误 5 — 10 个非随机、单层、弱代理来源组上的 bootstrap 不能支撑总体「显著劣于」

**round4 的说法**：§0 Q2 写「两个区间**都完全落在 0 以下** → P2、P3 **显著劣于** P1」，
并在 §7「明确不可作出」之外仍使用了「显著」这一总体性措辞。

**更正**：样本是 **10 个非随机抽取、单一 `free_axis_travel` 层、以 `WEAK_PROXY` 为参考**的来源组，
这样的 bootstrap 区间**不能**支撑关于总体的「显著劣于」。

**正确表述**：
「**在这批冻结的弱代理样本中，组级 bootstrap 区间完全低于 0。**」
不写「显著劣于」而不加限定。

## 勘误 6 — 第四轮评测的是逐帧空间定位，不是跟踪

**round4 的说法**：§0 Q6 与 `ROUND3_REVIEW.md` 更正 4 第 3 条写
「round4 用**真实视频**进一步确认……→『跟踪输出不应作为裁剪框来源』这一结论**加强**」。

**更正**：round4 的 P2/P3 调用的都是 Video-ORA-4B 的 **spatial grounding** 接口
（`arms_orarl.py` 用的是 `QWEN_SG_PROMPT`，逐帧独立定位），
**完全没有调用 tracking 接口**。
因此 round4 **不会加强**第三轮关于「跟踪复制 anchor」的证据。

**正确表述**：两条结论**分别陈述**：
1. round3（跟踪）：跟踪输出经常复制 anchor，无足够证据接入 AIC 裁剪；
2. round4（逐帧空间定位）：在这批冻结弱代理样本上，两种 OraRL 空间提示方式都低于当前 P1。

不得用后者为前者提供额外支持。

## 勘误后仍然成立的 round4 结论

以下不受上述六项影响，予以保留：

- 映射门禁计数：820 可用 / 75 missing / 92 time_uncertain / 0 ambiguous / 0 rate-field mismatch；
- 时间转换公式与 clip-local / source / offset 三套字段分列；
- 四臂 `WEAK_PROXY_IoU`：P1(0.7989) > P0(0.6993) > P3(0.6686) > P2(0.6294)；
- 组级 bootstrap 在本批样本内完全低于 0（措辞按勘误 5 限定）；
- P2/P3 二阶抖动为 P1 的 1.55×/1.96×，超过 1.25× 上限；
- 弱标签**没有动态宽度信号**（措辞按勘误 2 修正）；
- P3 主体描述 40/40 成功，额外 80 次调用、0.40 s/帧；
- 冻结 40 帧的参考框为 `WEAK_PROXY`，非官方真值、非人工真值、非 AIC 准确率；
- 本轮未把任何视频/帧/标签发给第三方 API，未使用跟踪输出作为裁剪框，未生成裁剪候选。

## 主管的后续决策（本轮据此执行）

1. **冻结当前 `P1` 空间定位模块**；不再做 OraRL 空间提示词搜索、跟踪接入或动态宽度实验。
2. 下一轮把资源投向**时序**：当前 43.4800 候选的 adapter 来自 **query-conditioned QVHighlights**，
   而 AIC 推理是 **query-free**，这是现有调用链中最大的**任务语义错配**。
3. 用第四轮已得到的 **820 条可映射 AIC 风格弱标签**（覆盖 **721 个 YouTube 来源组**，
   片段 5.238–32.134 秒）按 YouTube 来源分组冻结 train/dev/holdout，
   先复现 base 与 43.48 adapter，再训练 **query-free 时序 LoRA**。
4. 标签继续标记为 **`WEAK_TEACHER`**；开发集与留出集收益**只用于筛选**，
   **不等于赛事分数**；通过固定留出门槛后才允许测试集推理与候选打包，上传仍需单独决定。
