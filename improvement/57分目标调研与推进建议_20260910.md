# 57 分目标：调研与推进建议

调研日期：2026-09-10。此文是下一轮实验建议；本次调研未启动训练、下载大模型或增加官方提交。

## 结论

目前 41.22 分来自经过可靠性修复和多片段改造的零样本基线，尚未进行赛事任务微调。此前以“超过原基线”为停止条件，只获得 0.13 分提升，这个目标不足以支撑冲击 57 分。距离目标还差 15.78 分，不能把一次提示词修改、换大模型或短程 LoRA 当作可保证的解决办法。

建议顺序：建立与比赛一致的验证任务 → 分别诊断时间选择与裁剪 → 实现可调尺度的主体构图 → 加强时间候选与边界精修 → 用可信数据进行任务微调 → 独立留出验证后提交。

## 为什么必须同时解决时间和裁剪

[官方规则](https://www.aicomp.cn/tracks/tracks-6/4267.html)按同视频、同帧的裁剪 IoU 计分，逐视频计算后等权平均；输入不提供文字查询，裁剪结果包含位置和宽度。

对无重复、格式有效且存在匹配帧的单个视频，记预测帧数为 P、真实帧数为 G、命中帧数为 M、命中帧平均 IoU 为 q，则由规则可得：

`F_joint = 2 × M × q / (P + G) = F_time × q`

例如时间 F1 为 0.80、命中帧的裁剪平均 IoU 为 0.7125，乘积才是 0.57。这只是帮助理解目标的算例，不是当前模型的实测分解。数据集最终是各视频乘积的平均，不能直接把两个全数据集平均值相乘。

因此，补出更多高光片段未必增分：额外误报增加分母，而裁剪不准确会压低命中帧的贡献。

## 建议实施顺序与验收

| 顺序 | 工作 | 可验证的交付与决策 |
|---|---|---|
| 1 | 对齐评测与数据 | 取得赛方基础 evaluator 和带标注样例以核对边界；在非测试数据上准备同时包含时间与目标比例构图标注的开发集。未取得脚本时，诊断实现明确标记为内部工具。 |
| 2 | 分解损失 | 在同一开发集比较：真实时间＋预测裁剪、预测时间＋真实裁剪、端到端预测，另报时间 F1、空间 IoU、联合 F。先确认优先改哪里。 |
| 3 | 改造裁剪 | 镜头切分、语义主体定位、SAM 2.1 跟踪、多尺度目标比例候选、构图排序、镜头内平滑；同时保留最大裁剪候选。输出完整 x/y/w，不能把主体外接框直接当构图真值。 |
| 4 | 改造时间选择 | 优先在开发集校准保留与舍弃、空输出、片段合并及长度偏好，再用候选片段加密采样精修边界。长视频按统一的时长自适应策略分窗；窗口方案必须先消除非法区间问题，不能把历史诊断高分直接当成可提交方案。 |
| 5 | 小范围模型对照 | 先比 Qwen3-VL-4B 与 8B；有实际收益再测 Qwen3.5-9B。固定输入预算和数据，记录联合分、耗时、显存，不按模型宣传指标选冠军。 |
| 6 | 任务微调 | 来源和标签对齐通过后，训练无查询高光选择与构图候选排序；先做流程测试，再正式 SFT。避免只训练输出格式或只学会回答文字查询。 |
| 7 | 独立验证与提交 | 方案选择只使用开发集；新最终留出集按来源组隔离且只用于冻结后的验收。上一轮已经使用过的留出集不能重新宣称为全新盲测集。 |

第一轮最少跑四个对照：旧时间＋旧裁剪、旧时间＋新裁剪、新时间＋旧裁剪、新时间＋新裁剪。选出的组合再与其微调版本比较。这样能分辨收益来源，避免整套替换后无法判断是哪一部分起作用。

| [GAIC](https://github.com/HuiZeng/Grid-Anchor-based-Image-Cropping-Pytorch) | 裁剪候选排序的轻量对照 | 作者仓库提供数据与预训练模型入口，但原环境很旧；不能直接混装进现有环境，也不能假设其静态美学评分等价于赛事 IoU。 |
| [UniVTG 模型库](https://github.com/showlab/UniVTG/blob/main/model.md) | 轻量高光显著性曲线对照 | 作者提供 YouTube-HL、TVSum、QVHighlights 等权重；需要特征提取与域适配，其查询或类别设定不能直接等同于通用无查询高光。优先做单模型对照，通过后才考虑融合。 |

专门时间定位模型也有候选，例如 [TimeLens2-4B](https://huggingface.co/MCG-NJU/TimeLens2-4B)。但其模型卡标 Apache 2.0，而[仓库 LICENSE](https://github.com/MCG-NJU/TimeLens2/blob/main/LICENSE)仍存在学术用途等限制，必须澄清；而且它依然接受显式查询。这类模型先列入研究备选，不因为论文时间定位成绩高就直接替换主线，更不能把其 mIoU 换算成 AIC 的 57 分。

训练机本次读取到 RTX 6000 Ada、46,068 MiB 显存。8B 模型与分割模型顺序运行是合理的首轮试验规模；具体最大帧数和训练是否放得下仍需小样本实测。继续保留原权重与环境，遵守已有 GPU、磁盘总预算，不同时常驻多个大模型。

[Google AutoFlip](https://opensource.googleblog.com/2020/02/autoflip-open-source-framework-for.html)提供了镜头切分、显著主体分析、跟踪与裁剪路径平滑的公开设计依据。建议借鉴这条处理链，不把旧框架整体部署或单纯平滑当成达到 57 分的充分条件。

## 微调数据如何落实

现有 QVH v2 记录的候选规模为 train 1000 / dev 100 / holdout 100，来源组划分不重叠，但 `training_gate.json` 仍为 `passed:false`：媒体来源链待核实。解决方式应是补齐足以验证媒体身份的证据，或换用能明确追溯的小规模合法数据源；不能无限期停在“数据没通过”，也不能直接降低准入标准。

建议先做 200–300 个非测试视频的高质量联合标注试点，覆盖目标画幅和主要场景，优先确定标注规范、来源隔离和学习曲线，再增加训练量。这个数量是工作量建议，不是已存在的数据，也不是保证 57 分的样本量。可以用本地开放模型生成训练候选并复核，但未经复核的教师输出不能当独立验证真值。

[SACD](https://cg.cs.tsinghua.edu.cn/SACD/)提供主体构图图像与裁剪排序数据，可以补充空间学习；页面未明确列出完整使用许可，纳入前需核对。[RetargetVid](https://github.com/bmezaris/RetargetVid)提供 200 个视频的裁剪标注，但比例是 1:3 与 3:1，不能直接冒充本赛题 9:16/16:9 的真实框。其代码许可也不自动覆盖原视频权利。二者均是辅助候选，不能替代任务一致的最终验证集。

LoRA 可沿用 rank 16、alpha 32、dropout 0.05、batch 1、累积 16、学习率 5e-5 作为起始配置；实际序列预算通过小样本确认。先做 16 样本、最多 20 步的流程测试，然后依据开发集选择训练轮次。第一阶段冻结视觉模块，时间选择与构图排序分别验证。SFT 确实有效后再考虑偏好优化或 RL，不在缺少可信奖励和对齐标签时直接上强化学习。

## 57 分目标如何管理

将 45、50、55、57 作为官方成绩检查点，不预先给每项改动分配虚构的增分承诺。每次线上候选必须有开发集对照、冻结配置、来源隔离与可复现产物；总分变化只能确认整套方案的线上表现，不能据其手工反推测试视频标注。

真正值得优先投入的交付是：一套与比赛一致的诊断数据和评分、一个支持尺度变化的裁剪系统、一次可信的任务微调及对照报告。57 分可以作为冲刺目标，但现有证据还不足以承诺达到它。
