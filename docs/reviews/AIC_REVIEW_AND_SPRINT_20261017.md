## 1. 核心裁决

目前最有证据的瓶颈是：监督只覆盖有高光窗口，输出策略把相对排名当删除依据，封包层强制恢复空视频，以及外部摘要代理与正式联合分数错位。空间接口还缺少尺度自由度。它们比“8B 一定不够大”更有直接证据，但尚不能分解各自对官方失分的贡献。

首选路线：保留当前 8B 与可靠原生帧链，先测候选池是否足够，再训练可缓存的连续选择头，使用允许全保留、部分保留、全拒选的新输出合同。对照普通分类损失与更接近赛事集合分数的损失。每天五次机会用于比较少量通用候选方案，不要求五次独立重训。

备选一：若候选池上限不足，优先改覆盖/局部观察，暂缓排序训练。备选二：若外部诊断显示构图损失主导，则固定时间，尝试实例相关的中心与尺度候选选择。已失败的统一缩框、相对必删、微小端点扫描不重新作为新方向。

50 分相对 40.46 要增加 9.54 分，约为现分数的 23.6%。这里没有证据可保证达到；需要改善可影响较多视频的行为，而非不断产出只改变少量帧的近似包。

## 3. 已修复的两个链路缺陷及发布校验兼容问题

### 3.1 模型回答与接收决策的视频之间缺少源字节校验

`production_evidence.py` 核对 entry 与其自己的模型输入，`package_five.py` 核对 native clock 与 metadata，但 `package_math.combine` 原来没有把 entry 的媒体 SHA 直接与 clock 的媒体 SHA 连起来。不同视频可能有相同帧号与 PTS，因此时钟匹配不能替代媒体身份。

修复前合成反例：entry 源 SHA 为 `b×64`、接收 clock 源 SHA 为 `a×64`，其余 64 个采样 PTS、候选、视频 ID 匹配；ACTION `[20,30]` 仍被接受并新增 10 帧。

修复：`improvement/midnight_five_package_v1/package_math.py` 在应用任何回答之前要求合法 SHA256，并与该源 native clock 的 SHA 相等。相应 `check_pure.py` 新增不同源、缺字段、畸形 SHA 等反例。

这是后续 midnight 链的正确性修复，没有证据证明它影响了来自较早链路的 40.46 原包。不得声称修完必然提分。

### 3.2 文件路径绑定只检查词法位置

`improvement/midnight_production_unique_v3/mf_common.py::checked` 原来直接对未规范化路径执行 `is_relative_to(HOME)`。`HOME/../other_run.json` 和指向其他运行根的符号链接可以通过；即使文件 SHA 相同，也不能证明其处于登记根目录。

修复先解析真实路径，再检查根目录、常规文件和 SHA。在读取或哈希之前拒绝越界。新增同目录 `check_pure.py`，覆盖正常文件、错误 SHA、`..`、内外符号链接和目录。

### 3.3 正常修改与历史发布清单冲突

原 `tools/verify_publication.py` 按 10 月 15 日导出清单的 SHA 校验当前文件。修复源码或 README 后，正常变更也会被报告为文件损坏。直接重写旧清单又会破坏历史快照的含义。

现在保留原 `docs/publication_manifest.json` 的字节，增加可选 `docs/publication_updates.json`。增量清单绑定原清单 SHA，并记录每个受影响文件的旧 SHA、新 SHA 与字节数；旧清单未追踪的路径使用显式 null 作为旧 SHA。新增追踪不表示该文件此前一定不在 Git 中。核验器对合并后的当前文件检查实际字节，并拒绝错误基点、旧 SHA 不符、重复路径、目录越界和清单自覆盖。

`base_commit` 只是追溯元数据；本地验证绑定的是原清单字节，不会伪称已经验证远程 Git 状态。无增量清单的旧快照继续使用原行为。合成检查覆盖旧版兼容、合法修改/新增和错误清单、损坏文件等反例。

## 4. 四个比普通代码风格更重要的策略问题

### 4.1 相对排名没有“都保留”出口

`midnight_production_unique_v3/grammar.py` 的 `expression(n)` 对 `n>1` 限制 ordinary 恰有 `n-1` 个 ID，redundant 恰有一个 ID。`mf_common.prompt` 和底部第二次定义的 `validate` 明确实现 SINGLE strongest / SINGLE weakest。

当前已交付 ORDINARY 又通过 `package_math.deletion_indices` 的 `WORST_ALL` 使用 weakest，不能误写成线上一定删了 `n-1` 个。正确结论是：它强制产生可淘汰的相对最弱者，而缺少“多个候选都值得保留”的绝对判定。

两个片段都是真高光时，较弱者仍然可以值得保留。这种决策结构即使配上完美视觉理解也可能损害召回。其线上 38.83 与这一机制相符，但无法算出 1.63 分中多少由它造成。该策略是有意设计，故未作为无意 bug 静默修改。

### 4.2 最终封包不允许空视频存活

`temporal_family_native_v3/package_family.py` 的协议要求 `PRESERVE_ORIGINAL_D8_SOURCE_SELECTION`；合成后若某源为空，即恢复该源完整 D8 选帧，并再次断言全部 426 源非空。后续 `midnight_five_package_v1/package_math.py` 延续同类保护。

纯 `combine_events` 允许 DROP 事件并返回空集合，推理失败也有单独处理。因此应称为“非空保底策略”，不应说模型不支持空或官网要求非空。当前合同与交付记录中的保护包为 426 源全部非空、122,002 帧；未取得原始 complete decisions，未统计实际有多少源曾触发恢复。

新拒选模型若仍接这套 wrapper，学到的整视频拒选可能被覆盖。应建立新版本的可空输出合同，分别定义成功空输出、结构 UNKNOWN、执行失败；对 JSONL、构图合成、validator 做端到端空源检查。不能直接删掉旧保底策略然后赌分，尤其已有 EMPTY407 历史。

### 4.3 负窗口被训练合同排除

实际 `temporal_sft8b_full_v1/full_contract.py` 只把 `segments_clip_local` 非空的窗口加入注册集合，并要求训练行与之完全一致。原训练 704 父片段、602 来源、724 窗、5 轮、227 更新，loss 为 assistant 区间 JSON 交叉熵，显式负目标为零。

这既是数据分布问题，也是入口合同问题：往原 manifest 塞空目标会被旧合同拒绝。新训练应明确覆盖完整观察后的真负例，并对只被稀疏标注的区域使用未知掩码。未选中不等于负例；不能把其余整个视频都当背景。

原代码的 assistant mask、causal shift、末尾不足累积批次、adapter 更新与重载检查没有发现可据此推翻结果的明显错误。不要将全部失败归因于训练实现没生效。

### 4.4 空间只有中心，没有尺度

`next_round_v1/spatial_baseline.py::compute_crop_size` 始终取最大合法框；prompt 只要求中心。源比例等于目标比例时，输出必然全图，中心变化不会改变框。

这是输出能力限制。已失败的统一缩框只能否定已试全局方案，不能否定实例相关尺度；也不能由这一限制断言空间占据大部分官方损失。必须固定时间，单独在有原生比例参考的外部样本上判断尺度排序是否真的提高 IoU。

## 5. 技术债：处理在用入口，保留历史证据

项目有明显的版本分叉、硬编码路径和入口耦合债。`mf_common.library()` 从多个旧 Linux 目录注入 `runtime`、`codec` 等通用模块名；其他流程又分别实现不同强度的模块身份检查。相近封包库和运行状态机存在多个副本，修一份后下一轮从另一份导入的风险真实存在。

这不支持用剩余几天整体重写项目。当前原生时间、重叠事件并集、endpoint 64、adapter 恢复和错误终态已有实质检查。重构主线会引入复现风险，且不能修复错误监督。

给未来实验限定半天整理预算：

1. 一个运行配置，明确代码 commit、输入 manifest、模型 revision/adapter SHA、prompt、采样和策略版本。
2. 一个输入/缓存接口、一个 role 切换入口、一个结构化结果 schema、一个当前封包入口。新实验通过配置选择行为。
3. 保留旧冻结目录供复现；新入口不通过“扫描最新 vN 目录”选择实现。
4. 首次输入 QA 后缓存确定性视觉输入和映射；键包含媒体 SHA、processor 配置、采样、模型/特征层身份。
5. 用同一运行账本记录三类不同结论：工程检查、外部代理、用户官方成绩。只补必要证据，不为每个想法复制整套脚本。

原 `train_sft.build_example` 每例做两次完整 processor 调用以验证视觉前缀一致，而且跨轮重复。新入口可在首次验证后复用缓存；应先实测 decode/processor/forward-backward 分项耗时，不预设能加速多少。

## 6. 赛事反馈能做什么

本轮重新读了[赛题正文](https://www.aicomp.cn/tracks/tracks-6/4267.html)、[复赛通知](https://www.aicomp.cn/notice/notice-3/5307.html)和通知中的 0930 规则附件。官网确认每日五次、取历史最高，结果截止 10 月 23 日 20:00，作品材料截止 10 月 25 日 23:59。

对非空分母视频，公开公式为：

`F_i = 2 * sum(同一原生帧的裁剪 IoU) / (预测条数 + 真值帧数)`

双方为空记 1，单方为空记 0；逐视频等权平均再乘 100。合法且唯一的预测可分解为时间帧集合 F1 与匹配帧平均 IoU 的乘积；全局平均一般不能拆成两个宏平均数的乘积。

用户主张以最终分数决定方向是合理的。实际工作应分两层：外部数据提供逐样本学习信号和通用候选；官方分数比较这些候选的最终效果。五个总分不能识别数千区间的独立好坏，不能当作 8B 的逐样本 GRPO 奖励。

规则同时明文禁止测试人工标注、训练、人工修正、送闭源服务和“反向构造规则”。不能宣称逐视频试探隐藏标签不受限制。本方案不提出视频 ID 特判、删一条测一分、编码探针、从总分解出逐帧标签或将此类反馈重新作为训练标签。少量通用方案的模型选择不能被表述为已获赛方专项授权的无限榜单搜索。

只显示两位小数时，同分不是精确相同；固定评分条件下重复上传同一包也不会带来独立统计样本。+0.01 应保存其真实最优记录，但不自动证明发现了可迁移的官方偏好。[The Ladder](https://proceedings.mlr.press/v37/blum15.html)讨论的自适应榜单过拟合说明了为何要限制解释与搜索维度，而非禁止正常候选比较。

## 8. 唯一首选路线：候选覆盖诊断 → 连续选择 → 集合目标训练

### 8.1 先用有限外部参考区分方向

建议首批预算为 T48 训练来源、D24 开发来源、H24 一次确认来源。T48 可以从已有合规非测试训练来源中挑完整片段补标；D24/H24 必须与全部训练来源隔离。已看过的 SumMe/VideoXum 只能继续作为明示开发/回归材料，不能改名盲测。

覆盖动作、人物互动、生活/风景、演出、知识/演示、弱事件片段，并保留两种画幅、不同镜头运动。每源 30–60 秒，完整观察后标时间区间；分歧记录为软偏好或 UNKNOWN。T48 首批建议完整复核 24 个确无高光/普通窗口与 24 个容易漏选的正窗口；这是一项采样设计，不是把真实分布改成一半空视频。已有 724 个弱正窗只保留其已知监督，未知区域不制造负例。

筛选和标注首轮限在 6 小时人工预算内，不等待新数据集作者联系或无限下载。若不能取得足够完整参考，按实际来源数和覆盖范围报告；不补伪负例，也不把稀疏框插值自动当成完整真值。训练基础不齐时先做无训练连续分数小试。

同一外部来源上计算四个诊断量：

1. 现基线时间/空间表现。
2. 现候选池在参考标签下可达到的选择上限。
3. 保留同一时间集合、在合法裁剪候选中使用参考挑选后的空间上限。
4. 实际可运行的学习选择器表现。

第 2/3 项是外部 oracle 诊断，不是可提交算法，不预测线上分数。候选池 oracle 必须遵守实际候选/时间单元、并集、段数及帧预算限制；任意逐帧挑真值只能叫放宽约束的数学上界，不能当成实际选择器可达到的水平。只有完整时空参考的视频才能报告联合分；有完整时间、稀疏框时分别报告时间分和已标帧 IoU。

决策：若候选选择上限仅比基线高不到约 2 个外部联合分点，不值得把余下时间主要投入排序；若上限差明显（例如超过 5 点），排序值得先试。2/5 点是完整时空参考上的资源门槛，不是统计显著性结论，也不能套用到只有时间标签的样本。若时间候选上限不足，进入覆盖分支；若空间上限差远大于时间选择差，进入空间备选。

### 8.2 让一次模型计算服务多个候选包

首先保留现有未截断时间候选；从固定非测试开发数据设计一个有界的补覆盖机制，使明显漏选的窗口也有机会进入候选池。不要只在原候选中寻找更精细的“最弱者”。

首个实现优先采用一次窗口前向、按已验证的视觉 token/原生时间映射池化特征，再以轻量时间头输出每个时间单元的分数。若稳定取得这种映射改动过大，则对有界的候选短片段读取 Yes/No logits，作为无需重训的基准；先测 32 窗成本再决定是否全量。不得缓存全部层、全部生成步骤的巨大 hidden states。

Qwen3-VL 当前输入的 64 帧经过 temporal patch=2，对应 32 个视觉时间组；必须依据实际 `video_grid_thw` 和 patch 时间映射池化，不能假设有 64 组独立时间特征。如果用语言主干视觉位置的 hidden states，应考虑因果上下文限制，并由能融合整窗的时序头整合前后信息。特征分组不等于获得了更密集的真实观察。

单次缓存记录 `source_sha / window / native_ordinals / exact_pts / model_revision / adapter_sha / processor_config / feature_layer / candidate_policy`。现有 pixel 缓存不等于已有 hidden-state 缓存。主干或输入改变必须重新生成特征；只改变小头和选择策略时复用。detached 特征仅用于训练小头；后续 LoRA 必须重新进行带梯度的主干前向/反向，并重建受影响缓存，不能从旧缓存反传至主干。

小头以实际 hidden size 为准，先用 `d → 128/256 → score` 或小型一维时序卷积，参数约百万量级。采用源码实际清点而非名字估计。当前驻留 8,782,459,120 参数，9B 上限余量为 217,540,880；时间/空间头及任何辅助模型都合并统计，不能通过先后加载或量化绕开总参数口径。

输出必须支持：全部候选保留、部分保留、全部拒选。拒选只接受成功模型结果；坏 JSON、超时、视觉错位另记失败。新可空包合同必须与旧非空恢复合同区分，不能仅换 loss 后复用旧 wrapper。

### 8.3 两个训练臂，只改损失

H-BCE：冻结同一主干，在相同特征、T48+既有可用监督、来源采样和训练预算下，学习可观察高光的分类/成对偏好。

H-SET：相同结构和数据，以 H-BCE 为对照，加上按视频平均的软集合 F1 目标。对于完整时空参考，可进一步使用 IoU 加权集合目标：

`L_joint = 1 - mean_i [ 2 * sum_t(s_it * y_it * q_it) / (sum_t(s_it) + sum_t(y_it) + epsilon) ]`

这里 `s` 是选择强度，`y` 是该参考的高光指示，`q` 是当前候选框与该参考框的 IoU。完整监督样本中，`sum(y)` 包含该窗口/视频的全部真值高光帧，候选池之外的真值也不能漏算，对应 `s=0`。重叠候选必须先映射为唯一原生帧/时间单元；不可把重叠帧重复算进分子。若单元覆盖多个原生帧，应按覆盖的帧数加权，不能简单以单元秒数替代官方帧计数。

全负样本单独使用负例分类/拒选损失，避免零分子使选择头得不到有用梯度。30–60 秒负窗口只证明该窗口为负，不能把整条来源视频标成负。弱正样本仅参与已知正例/偏好项，完整集合项只用于完整观察的样本；若做掩码诊断，UNKNOWN 同时从相关分子和预测分母排除，结果也不是完整宏 F1。只有时间标签时令对应实验明确为时间 soft-F1，不伪称已经优化联合 IoU。若使用成对偏好，加入一个可保留全部的绝对锚点；不能只学一个永远要产生最弱者的排序。

先在缓存上各训练一个小头、最多两个学习率和一次来源确认。建议学习率从 `1e-3` 的小头 AdamW 起步；这是试验起点，需开发损失和校准检验，不是已验证最优值。不要立刻更换 8B 主干或全量重训。

若小头确实学到可迁移区分，才用一天中的一个约 5 小时预算做少量 LoRA 继续训练，并重建相应特征。原 724 窗×5轮的训练完成记录为 16,455 秒（约 4.57 小时）、峰值分配约 20,532 MiB，这只是历史任务用时；新序列、采样与模型配置的成本必须重测。

### 8.4 外部验证服务决策，保留有理由的探索

主要统计单位是来源/视频，不是大量相关的帧或同源窗口。报告宏平均改变量、逐源分布、来源 bootstrap 区间、空/非空混淆和两种比例的框表现；不沿用“一源降 0.01 就否决全局改进”的僵硬通用门。

外部代理用于排除损坏、崩塌、候选丢失和明显退化，不能宣称它预测官方分数。没有完整联合标注时也不必无限等标注：时间臂固定空间，先形成可解释候选，并在每天预留的一次探索额度比较真正不同的方案。该包标作未证实收益，不能把其工程 PASS 写成科学胜利。

H24 最多确认一次；看过之后登记曝光，不再反复改阈值并称独立确认。弱证据可以做竞赛取舍，但必须如实降低结论强度。

## 9. 每天五次的具体用法与截止前日程

### 9.1 第一轮有训练结果后的五个候选

## 10. 空间备选与教师路线

### 空间只做有诊断依据的实例相关改变

固定最佳时间和预测帧数，每个锚点从最大合法框及少量尺度/中心候选中选择。允许最大框获胜；未知时保留原框。尺度组可以在外部开发中从 `{1.0, 0.9, 0.8, 0.7}` 作起始候选，再由人类原生比例参考训练选择器；这不是四个统一缩框提交。

先比候选池 oracle 与实际选择器：oracle 好而模型仍全选最大框，应改监督/选择能力；oracle 也无改进则停。时间平滑限制在同一镜头内，并对尺度使用连续几何约束。仅有自由比例框或稀疏标签时不把改比例/插值后的框冒充原生密集人工真值。

此分支首轮只用已获准的外部来源；LIVE-YT 来源/使用边界未齐且用户不联系作者的旧约束继续保留。无需为本计划重复等待该数据集。

### Gemini 的三个事实

1. 当前 TIME 所审计的 808 条标签实际来自豆包 1fps，没有同源同样本 Gemini 对照，不能说已证明 Gemini 不行。
2. [Gemini 官方视频文档](https://ai.google.dev/gemini-api/docs/video-understanding)明确默认静态视频处理为 1fps，快动作可能丢细节。原视频入口不意味着看了每帧。教师对照应比较学生同样可见输入与更密/带音频输入；只有后者才懂的标签不能直接硬灌给前者条件的学生。
3. [Gemini API 当前条款](https://ai.google.dev/gemini-api/terms)限制利用服务开发竞争模型；付费并无自动豁免。该文字不是对一切专用训练的一概禁令，也没有明确给予本项目蒸馏 Qwen 的许可。不能把 Google AI Pro 会员等同于训练授权。

因此新主线优先用已获准外部标签、有限人工复核和许可合适的开源教师。若将来适用授权明确，Gemini 首试只做 24–48 个非测试窗口的同可见性对照，输出可见证据与偏好，允许未知。先证明改善学生跨来源选择，再考虑扩大；不把“教师回答更漂亮”作为扩标理由。

## 11. 资源止损与最小 Linux 信息

建议把 +0.2 官方分作为是否追加一天 GPU 的资源信号之一，而非统计显著性阈值；小于该值的真实最好包仍保存。一个方向两次有实质区别、输入完整的候选都下降时，停止微调附近小数点，回看候选覆盖或目标错位。

原训练 loss 下降而跨来源选择不升，停加 epoch。候选池上限不升，停加排序容量。老师仅凭学生看不到的帧/音频获胜，先修观察条件。空间候选 oracle 无增益，停训尺度选择器。大面积输出空或恢复原包时先查状态/封包合同，不把工程异常解释为新偏好。

执行方只需补取以下小量信息，无需传测试媒体：

| 信息 | 具体内容 | 用途 |
| --- | --- | --- |
| 在用入口 | command、源码 commit/SHA、配置、模型/adapter SHA | 避免改了未调用副本 |
| 已保存来源绑定 | 每条 production entry 的 source SHA 与相应 clock SHA 的相等检查及错误计数 | 判断本轮源身份缺口有无实际影响 |
