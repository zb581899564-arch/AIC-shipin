# 豆包2.1 Pro实际小试结果

可以和Gemini配合做候选标注。当前分工建议：Gemini原生读视频选高光，本地按原生PTS抽图，豆包读原图标构图框，实际裁图后再复核。豆包首稿的竖屏框存在明显漏主体；看自己的裁图后能纠正，但不能仅凭输出合法就直接当高质量训练标签。

## 实际完成

同一TVSum跑酷视频 GsAD1KT1xo8，640×360、145.3452秒。豆包工作客户端的模型选择器实际选为2.1 Pro。

| 输入方式 | 实际结果 |
| --- | --- |
| 本地路径直接Read MP4 | 工具拒绝binary .mp4；没有观察帧 |
| 上传同一MP4为附件 | 接受视频卡片，但模型仅获得文件引用，再次Read失败；没有观察帧 |
| 本地8张原生关键帧PNG | 成功，8帧×16:9/9:16共16框 |
| 13张带时间戳拼图，146个1FPS原生采样 | 成功，生成18段粗高光候选 |
| 原图+初稿框+实际裁图的8张反馈图 | 成功，生成独立image_v3复核版本，保留image_v2 |

已展开并核对8张原图、13张时间轴拼图及8张复核图的实际Read工具路径。两次图片版输出均有8个唯一帧号、准确PTS、合法框比例和边界；所有16:9框均为原图全幅，几何通过不代表构图优越。不是4356帧的全视频逐帧精标，也没有验证整段框的动态连续性。

本次限制属于该工作客户端的工具与附件输入链路，不能据此断言豆包模型本身完全没有视频能力。原始失败输出的空events/UNKNOWN保留为未观察，不作为负标签。

## 高光效果

| 标注来源 | 候选段数 | 区间并集时长 | 选中帧的人工重要性均值 |
| --- | ---: | ---: | ---: |
| 之前Gemini原生MP4小试 | 15 | 60.000秒 | 2.215 |
| 本次豆包1FPS图片小试 | 18 | 64.345秒 | 2.208 |

独立读取已下载的TVSum20人原始重要性向量；向量与顺序解码的4356帧数量一致，按源帧序号对照。全视频平均2.002，未选中部分分别约1.852/1.838。两者确实更偏向人工评价较重要的部分，但本条视频平均值非常接近；输入模式和选择时长不同，不能据此宣布哪一模型更强。这不是准确率、精确边界真值或AIC官网分，评分也未提供给模型。

豆包补出了Gemini未列出的约42秒跳台和108秒跳墙；但把139秒后的墙边平衡行走也列为候选，且将120–122秒描述为普通停留，可能漏掉动作。Gemini包含119–124秒。1FPS会漏掉起跳/落地，双方分歧需要看原视频或密集原生帧；不直接并集成最终标签。

## 构图效果

首稿真实裁图暴露了文字理由与坐标不一致：k02–k04说保留纹身女人，却把她切出框；k05（50.517秒）几乎漏掉蓝衣运动员；k06切身体左侧；k07切掉翻栏杆者的头。前5张同源帧对照没有证明豆包首稿明显优于Gemini。

让豆包实际看自己的裁图后，8张9:16框均重新定位：

| 图组 | 实际复核效果 |
| --- | --- |
| k00/k01，人群遮挡 | 减少蓝色后背占幅，更多背包和人脸；仍是普通过渡画面 |
| k02/k03/k04，人群主体 | 找回纹身女人的头和身体；仍需舍弃其他人，有前景遮挡 |
| k05，蓝衣运动员 | 比初稿明显改善，但仍切到身体左侧；原图本身脚部已到下边界，不能称全身完整 |
| k06，台阶动作 | 主体保留明显改善，手脚贴近边缘，右侧围观者舍弃 |
| k07，翻栏杆 | 找回头部和躯干；脚腿被舍弃，复核理由明确记录固定竖屏比例取舍 |

这些是实际裁图的定性检查，没有人工构图真值，不能报框准确率。image_v3接受了人工问题提示，不能当独立盲评。复核流程有价值，输出仍需筛选。
