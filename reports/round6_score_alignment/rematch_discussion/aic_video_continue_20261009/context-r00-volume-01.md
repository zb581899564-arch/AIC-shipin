2．最容易使本方案“看似训练成功、实际失效”的问题

冻结输入 embedding，再配上处理不当的 reentrant gradient checkpointing，可能导致语言部分没有梯度，而新 MLP 仍正常降 loss。

PyTorch 官方文档明确说明：reentrant 版本要求至少一个输入和输出具有梯度要求；不满足时，该 checkpoint 区段不会有梯度，non-reentrant 版本没有这项要求。因此，验收不能只看 loss 下降和头梯度。建议在实际安装版本支持下明确使用 use_reentrant=False，并检查真实路径。

4．日内流程

**批次开始前：**核当天余额，选出已就绪的 1–5 个候选，登记唯一变化、证据等级、资源预算、代码/权重/配置哈希。A 不需要等尚未训练出的 C 的权重哈希；但每个候选必须在获知其自身成绩前冻结，在同一比较批次里不能边看分数边改下一行。

因此，**即使某个窗口没有值得保留的内容，当前生产算法也必须给它找出一段。**这与官方明确允许无明显高光视频输出空预测不同。

但这里不能做一个过于简单的“修复”：只把语法改成允许 []，就宣称学会拒绝。现在训练全是已知正窗口，模型缺乏什么时候应该不选的监督。贸然放开空输出，也可能把原来的误选换成大量漏选。

更深一层，当前虽然没有把 UNKNOWN 显式写成 BCE 负标签，但区间 SFT 要求模型输出一份完整列表并结束响应，仍会让它学习教师的“选哪些、到哪里结束”的偏好。没有显式负标签，不等于没有教师遗漏偏差。

所以这项修正必须包含：新的完整观察监督、训练目标、提示词、语法、解析器和合法空的合成测试，不能只改其中一行。

3．空间端存在一个可直接构造反例的坐标解析错误

当前空间提示词已经要求 0–1000 的整数坐标，这点是对的。但 inference/baseline_qwen3vl.py::parse_focus_norm() 又对每个坐标分别猜单位：

Python
if value <= 1.5:
    norm = value
elif value <= 1000.0:
    norm = value / 1000.0

因此模型合法输出：

JSON
{"center": [1, 500]}

按照提示词应解释为：

纯文本
[0.001, 0.5]

代码却会解释成：

纯文本
[1.0, 0.5]

**接近左边缘的位置，被解释到了最右边。**此外，解析器还接受从非 JSON 文本末尾提取数字，这使“最终框合法”不能等同于“坐标语义正确”。

建议新版本只接受一种明确坐标合同：严格 JSON、恰好两个有限坐标、范围符合声明，统一除以 1000；不要逐坐标猜单位。无效输出进入有记录的重试或失败流程，不能悄悄猜成合法框。

**这是确定的代码缺陷，但出现频率尚未统计，不能声称修了就能涨几分。**先用非测试原始输出统计影响面，再决定是否形成修复包。

5．输入预算需要明确化，但别把已经修好的长度限制再当作故障

Linux 训练使用的 min_pixels/max_pixels 顶层设置，并不能直接证明视频每帧严格落在所写的像素预算内。当前生产协议已说明它继承的是实际 processor 默认视频预算；开发入口限制 8192 token，生产扩大到 16384。工程上能生成，不代表这种实际输入分布差异已经经过质量比较。

这里不用另造一套方案：Mac 迁移代码已经给出了更清楚的实现范式——显式传视频 size，再从 video_grid_thw 检查实际处理后的每帧像素和总序列长度。这个合同可以在 Linux 复用，完全不需要依赖 MPS。

但我不建议因此马上把 Linux 一律降到 Mac 的 32768 像素。明确预算是工程修正，选更低预算是质量取舍，二者要分开。

6．时间候选的空间框并没有真正固定

production.py 先得到选中帧，再把选择间断视为新段，随后安排锚点。这意味着时间模型换一份选择结果，同一个源帧也可能落在另一组插值锚点之间。

它未必使结果更差，但会污染归因。**新的非测试对照应先按源视频与镜头固定空间锚点，再让各时间方案读取同一份空间场。**旧 37.63 包保留原样；不能为方便比较改写历史包。

三、下一轮微调主案：保留 8B，改变监督，而不是马上换回稠密头
我的唯一训练主线

当前 8B 时间 adapter 为起点，补一批完整观察、通用高光语义、允许空和多段的新监督，做一次低学习率区间 SFT 续训。第一轮不加二元头、不加空间 LoRA、不上 RL。

这不是认为稠密头无效，而是当前最难的问题已经明确是数据语义。再把同一份不完整标签换成另一种输出头，仍然绕不过去。继续用已经跑通的区间接口，可以把有限时间集中在模型是否学到了新的选择依据，而不是重新调试另一条训练链。

1．新数据具体怎么做，不再无限追查旧教师记录

旧教师缺少的 prompt、完整观察范围和原始响应已经是停止原因，不值得继续花几天试图从不完整文件里“证明它其实完整”。我建议启动一个有界的新监督构建任务：

项目	建议安排

这里有两个实际限制必须说清楚：

**第一，32B 的量化运行、权重来源和磁盘峰值本次没有验收。**不能说“4bit 大概能放下”就直接下载，更不能先下载完整 BF16 权重再量化，却只把量化后的大小记进 80 GiB。只有权重、临时缓存、现有资产和运行峰值都能容纳才启用；不新增租卡要求。

**第二，新教师输出仍是弱标签。**更大模型、两次答案一致、或教师声称“看完整个窗口”，都不等于人工真值。需要记录真实输入覆盖，并抽查它是否只是偏爱更长区间、把所有窗口都判有高光。独立参考不足时，结果继续标注为弱证据，不能包装成真值。

**止损出口：首个工作日仍无法形成有解释依据的正负监督，就不启动这次语义续训，先推进后文的低成本推理候选。**不会再让“补数据”把全部交付无限期扣住。

3．合法空要一次贯通，不留半条链

新版本应同时修改提示词、目标校验、生成语法、解析器、时间选择、全空情况下的空间调度和封包。

尤其要覆盖：一个窗口为空、一个视频全空、整个批次没有空间请求。当前空间推理存在要求锚点请求非空的检查；不能只让时间端返回 []，随后在空间阶段因为没有锚点而失败。

正确状态必须分开：

合法空是预测；解析失败是算法失败；没有生成是执行失败。

4．窗口重叠不作为第一轮默认加料

当前是 30 秒不重叠窗口。暂时保持，先减少同时改变的因素。

只有新非测试诊断明确发现事件被切在窗口边缘时，再登记一个 30 秒窗口、15 秒步长、按中心区域归属输出 的候选。不要简单把两个窗口所有区间取并集，再把覆盖增加称为事件完整性提高。

四、空间下一步：先决定值不值得训练

我不建议现在立刻安排“8B 空间 LoRA 再试一次”。此前空间弱监督试训已失败，双比例可靠参考也不足，盲目扩大同样监督没有新依据。 
context-p01

空间工作分两层，且第二层必须由第一层触发：

**先做低成本诊断。**修严格坐标解析；在身份可信的非测试框上比较实际中心误差和固定最大尺度上界；分别报告横、竖目标比例。有多少有效参考就报多少，稀疏正例框不能假装成全视频联合分。

**确有尺度瓶颈，再做一个空间候选。**使用同一未微调 8B，改为目标比例约束下的中心与尺度决策，经过非测试构图参考筛选后，形成只改变空间的完整包。不是把所有测试框统一乘 0.8，也不是将检测主体框直接当构图真值。

第一轮仍不加检测器、分割器、跟踪器或音频大模型。现在需要证明新的自由度确实有效，不需要让参数账和部署链重新复杂起来。

五、怎么又快又好地评，而不是再花几天只出报告
开发评估分成三张表

**第一张：生产一致性。**同一输入合同、同一生成约束、同一时间映射、同一空间算法；记录合法空、解析失败、推理失败，不混为一个零分。

**第二张：模型质量。**旧标签上的结果叫“旧教师一致性”；新完整观察标签上的结果叫“新教师完整窗口一致性”；具备独立参考的部分单列。报告视频宏 P/R/F1、空误判、零交集、短事件与多段情况。当前代码已有视频宏指标，但主要决策基于来源组宏 F1；新协议应让官方对应的视频宏口径成为主要点估计，来源组负责成组重采样。
