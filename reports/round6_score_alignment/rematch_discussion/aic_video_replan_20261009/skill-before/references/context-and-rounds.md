# 信息包与轮次记录

完整是指足以让每位参与者独立理解当前任务和全部决策依据，不是无差别外传整个磁盘或所有无关聊天。

## 信息包规则

1. 基础包包括：用户当前原始诉求与修改、关键历史指令、成功标准、截止/预算、禁止项、所有已有方案与失败、真实观察和测量、已做/未做事项、资源与实现约束、必要代码/配置原文、来源文档和未决问题。不能只传自己的推荐。
2. 本地路径与链接不等于文件内容。对决定有用但参与者无法访问的资料，应提取获准共享的原文或必要代码进 .md，并列出来源、时间、SHA/版本和缺失范围；不能宣称“全上下文”同时把关键证据留在不可读路径。
3. 保留用户和外部 AI 可见回答原文，并标明作者、轮次与任务。长文件可以拆成完整 .md 卷宗 + index.md，所有相关卷必须上传。只有差量包、模型口头复述和“详见上文”不满足本规则。
4. 不上传密码、令牌、私钥、账户会话、个人无关隐私或不获准共享的数据。涉及这些内容时用明确的“已脱敏/未共享”标记，必要时请用户决定安全替代材料。缺失影响推理时标为阻塞，不能以隐私为名悄悄删掉失败证据。
5. 版本只增不覆写，文件名 context-r00.md、context-r01.md 等；每个新版重新包含任务基础和累计讨论，附本轮修改列表。发送前由主控完整读回，对文件计算大小与 SHA。
6. 每个外部席位实际附件上传后，要在 ledger.json 区分“待上传 / 处理完成 / 已发 / 已确认读取 / 完整回复 / 阻塞”。模型复述关键约束是读取的辅助证据，不等于数学上证明每字均读。

## 回合安排

- r00：建共享基础包；主控写独立初始意见；普通参与者分别做独立分析。
- r01：包含所有 r00 原始意见和主控分析；普通参与者交叉挑错、回答最强异议并修订。
- r02（需要时）：核清重要分歧，再比较候选。避免为了显得热闹继续重复；收敛仍须留出反对意见。
- p01：第一次 Pro 决策，收到的不是缩略会议纪要，而是截至此刻完整 MD 卷宗；可附简短决策提要作为导航，不替代正文。
- 后续：每次 Pro 意见先进入完整包给普通席位；确有重大争议则再开展至少两轮交叉讨论，再使用 p02/p03。达成足够可靠方案可提前结束。

普通参与者应回答：我同意/反对哪些具体主张；证据等级；最强反例；未知和验证成本；我是否改变立场及原因；推荐行动和拒绝/停止条件。主控也必须按同样标准回答，不能仅写“已综合”。

## Pro 预算簿

用当前可用 Python 调用 skill 的 scripts/pro_budget.py；以下路径均相对于 skill 安装目录解析为绝对路径后再执行：

- init --ledger 讨论目录/pro-budget --task-id 本任务ID --already-used 已确认的次数
- status --ledger 讨论目录/pro-budget
- reserve --ledger 讨论目录/pro-budget --packet 本次完整context.md
- outcome --ledger 讨论目录/pro-budget --slot 本次编号 --status completed或uncertain或not-sent --note 可见状态的简洁说明

每次 reserve 最多占一次，保守地占用三次预算之一。脚本不核网页身份，不证明附件或回复真实；这些由 computer use 及 ledger.json 记录。not-sent 也不自动退回预算，避免不明发送造成超额；确实需要改变限制必须取得用户明确新指令，不能自行删预算文件。

预留的重复检查与占槽使用同一把本地锁，同一信息包并发请求只预留一次。预算锁尚在或中断后残留时报告 BUDGET_LOCKED；不能自动删除未知所有者的锁，不以另建预算簿绕过。此锁不控制浏览器，也不证明消息送达。

若用户已经有同任务 Pro 消息，将已确认次数写入 already-used；无法确定要先询问。只上传当前决策需要的实际完整 MD，不能用模板空文件预留后当成完成讨论。

## 主控兜底裁决

裁决记录必须包括：触发原因（偏题/无效发散且不调用Pro/额度用尽）、原目标、各参与者的关键异议、采用和放弃的方案及证据、未知风险、适用范围、验证/停止条件，以及是否缺少 Pro 认可。

主控可以拒绝非 Pro 的意见，但不能靠权威弥补缺证据；与 Pro 的技术意见冲突时不能悄悄覆盖，必须显式报告。任何必须由用户选择的费用、公开、数据、破坏性或新实验授权仍交用户决定。
