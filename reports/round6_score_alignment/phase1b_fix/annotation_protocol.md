## 2. 角色与身份

| 角色 | 谁来做 | 必须留下的证据 |
|---|---|---|
| 标注者 | 真人；**不得**由模型或脚本代填 | 页面 `标注者` 字段（导出 `identity.annotator`） |
| 复核者 | 另一名真人 | `identity.reviewer`；复核 ≥20% 且覆盖全部争议样本 |
| 执行/审计（本 Agent） | 只准备并验证工具，**不填语义** | 本协议、`test_results.json`、`ui_e2e/`、`RESOURCE_USAGE.json` |

- 未复核时 `reviewer` 必须留空，`label_status` 保持 `WEAK_HUMAN_SPARSE_PENDING_REVIEW`；
  **不得仅改字符串就升格为“已复核”**。
- 机器生成的任何标注都是弱标签，须显式标注来源。

## 3. 逐样本操作（含精确帧要求）

1. 启动精确帧服务（`frame_server.py`，仅回环）并打开 `annotate.html`；页面右上角显示服务连接状态。
2. 选样本 → 用视频粗定位 → 在“精确帧”区输入帧号 → `取精确帧`。
   页面显示解码帧静态图，并给出 `index / pts / time_base / 图像 sha256`，且核对浏览器收到的字节一致。
3. `显示/编辑框` → 拖动移动、拖右下角改宽度。框高按 `h = w·th/tw` 推导，宽度不得超过
   `最大合法裁剪宽度`，且必须完整落在源帧内。
4. 记区间：填“起始帧 / 最后保留帧” → `添加区间`，导出为 `[start, last+1)`。
   **每个端点各自记录定位方式**；只有该端点帧被解码核对过才记误差 0。
5. `以当前帧添加关键帧` → 存 `box_xyw` 与该帧的溯源。
6. 选状态；`确认无高光` 必须勾选确认框，且**不得残留区间/关键帧**（残留即报错，工具不会静默清空）。
7. 填标注者（必填）、说明；有复核再填复核者。`导出参考 JSON`。
8. 随时 `导出草稿` 保存进度；刷新后用 `恢复自动草稿` 或 `导入草稿` 恢复。

## 4. 校验规则（JS 与 Python 同一套）

以下是导出/导入必须通过的检查（任一失败即拒绝导出并列出问题）：

1. **数值**：`x, y, w, sec` 必须是有限实数；`NaN`、`±Infinity`、`true/false`、字符串一律拒绝。
2. **区间**：`0 ≤ start_frame < end_frame_exclusive ≤ N`；空区间、越界、重复区间拒绝；
   相邻区间合法；`end = N` 合法并给出“覆盖最后一帧”提示。
3. **时间一致性**：`*_sec` 与 `frame / fps` 的偏差 > 0.5 帧即拒绝。
4. **关键帧**：帧号在 `[0, N-1]`、同一帧不得重复；框在帧内、满足目标比例、宽度不超过最大合法值。
5. **溯源**：每个端点/关键帧必须有溯源；`decoded_frame` 必须给出与记录帧一致的 `decoded_index`、
   `decoded_pts_sec`、`time_base_sec`、`image_sha256`；只有 `decoded_frame` / `pts_sample` 可记误差 0。
6. **状态一致性**：`UNANNOTATED`/`UNCERTAIN` 不得携带区间或框；`HAS_HIGHLIGHT` 至少一个区间；
   `NO_HIGHLIGHT` 必须显式确认且不得与残留区间/框冲突。
7. **身份**：标注者必填；`reviewer` 未复核时必须为 `null`。
8. **导出语义**：`exportable_as_reference` 只在通过校验且模式可产出参考时为 `true`；
   稀疏关键帧**始终**导出 `coverage="sparse"`，绝不补成全视频参考或生成联合分。

失败时：不产生任何可消费参考（`reference = null`），问题逐条写入导出结果与页面提示。

## 5. 草稿与恢复

- 草稿文件 `p1b_annotation_draft_v2`：含 `sample_digest`（样本 ID + 媒体 SHA-256）、
  `core_version`、`interval_semantics` 与每个样本的标注。
- 导入时校验：协议版本、区间语义、媒体身份、未知样本、旧闭区间字段 → 任一不符立即报错。
- 覆盖当前未保存工作前必须二次确认；有未保存改动时关闭页面会触发离开提示。
- 自动草稿只存在本机浏览器存储，不外传。

---

## 6. 复核要求

1. 复核 ≥20% 样本，并覆盖全部争议样本（`UNCERTAIN` 或存在分歧）。
2. 复核者独立打开媒体核对帧号与框，不得只看导出 JSON。
3. 分歧保留双方记录，不做静默合并；复核结论写入 `复核者` 与说明字段。
4. 是否升格 `label_status` 由总控决定，且必须附复核记录与协议更新。

## 7. 明确禁止

- 不标注官方测试视频；不把媒体/帧/标注上传到外部服务或交给外部模型生成。
- 不由执行 Agent 或脚本代替人工填写高光/无高光/构图框。
- 不为让候选“好看”而修改已导出的标注；修订须新增记录并注明原因。
- 不把这 8 组当盲测留出集；后续扩到 80 组时试点及其同源视频不得进入新 holdout。
