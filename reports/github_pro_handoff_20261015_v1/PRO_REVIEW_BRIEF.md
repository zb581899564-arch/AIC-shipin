## 2. 任务、评分与约束

任务是通用视频高光选择与目标比例构图，复赛提交426个视频的原生帧及裁剪框。时间选对而框不准仍可能失分。正式参考真值不可见。

已保存的官方规则审计解读：对相应非空分母视频，`F_i = 2*S_i/(P_i+G_i)`；`S_i`为匹配原生帧的构图IoU总和，`P_i/G_i`为预测/参考帧计数，逐视频等权平均后乘100。内部实现是根据公开说明重写，不是拿到的官方evaluator。空集、重复帧、坐标约定等应以原附件为准。

因此在合法唯一同帧匹配条件下，联合分可写成“帧集合F1 × 匹配帧平均IoU”。外部纯摘要F1不能直接估计正式联合分。不能把40.46宏平均分除以二当每个视频的新增阈值，也不能从一次总分反推错误视频或逐条修正。

## 4. 模型与训练的事实

基座为`Qwen/Qwen3-VL-8B-Instruct`，原训练固定revision `0c351dd01ed87e9c1b53cbc748cba10e6187ff3b`。现链实际物理驻留总参数 **8,782,459,120 = 8.78245912B**，包括仍驻留而在某角色关闭的TIME LoRA，不能关adapter后少报参数。

现用TIME训练记录：704个父片段、602个来源、724个窗口；5轮、227次optimizer更新；assistant区间JSON交叉熵，AdamW，lr=5e-5、grad_accum=16、r16/alpha32、dropout0.05、bf16，最后checkpoint而非根据测试选优。原训练max64帧、30秒窗口等细节见原config，不要把后续native输入修复误写成原训练就完全一致。

**这批TIME训练标签不是Gemini。** 已完成教师语义审计的808条均声明`api_doubao_doubao-seed-2-1-pro-260628`，时间/空间观察频率1fps，schema为弱训练标签。原训练报告`negative_targets_created=false`，教师训练/开发显式negative行计数0。没有同源同样本的Gemini/豆包受控对照。

这支持“监督非空提取为主、缺少明确负目标”的事实，尚不能证明缺负例是唯一瓶颈，不能证明豆包必然差于Gemini，更不能证明未经选中的时间全是负例。群聊经验不是受控实验。

当前时间推理基本是短窗native64真实帧、受约束JSON生成，原生PTS/帧身份与CPU实际processor张量经过独立检查；历史试过密度/采样/边界/复核等。RAW成功、工程通过与语义正确是不同证据。

空间使用同一8B基座、关闭时间adapter，输出重点中心，再取目标比例下最大合法框；镜头内max-gap8锚点线性插值形成连续源场。模型没有在此基线中预测尺度。源图与目标比例相同时，最大框就是全图，改变中心也不改变框。这是代码能力限制，**不是空间误差占正式失分多少的测量**。

## 6. 外部小试做过什么，为什么不足以继续盲推

SumMe25与VideoXum多批源已经曝光，不能再称新盲测。SumMe是人工摘要；VideoXum是事件文本引导的人工摘要。当前VideoXum比较使用全评审平均配对duration-F1及precision/recall，通常4源开发、冻结后4源新确认。标注未选不是明确ORDINARY，duration权重也不等于原生帧计数，更没有赛事空间GT。

历次小试保留原科学门和真实失败，不因后来的解释改判：

- 单视角补召回：140真实调用及首次独立QA；确认宏F1 .32047108→.33851842、recall .64888406→.74921899，但一源F1下降.01583824，超过事先.01门，STOP。
- 双视角KEEP交集：76调用；F1 .26297336→.27200132、recall .44984393→.47480765，precision .21932814→.21773415，原精度不降门失败。新增77帧/2源。不能以更多召回替换原门。
- 每个新增段自身须有积极证据的准入：开发10调用通过；新确认71调用，F1 .3311046567→.3278489721、precision .2390208546→.2124752380、recall .6379196559→.7347377951，多门失败。

- 相对删弱ALL_WINDOW_WORST：开发/新4确认原门PASS而全量线上38.83。这是最直接的代理外推失败证据，不重写原PASS。
