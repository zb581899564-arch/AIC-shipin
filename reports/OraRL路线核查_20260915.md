# OraRL 路线核查（2026-09-15）

## 已确认

- 作者仓库公开 Video-ORA-4B 和 Video-ORA-9B，底座分别为 Qwen3.5-4B、Qwen3.5-9B。现有 Qwen3-VL adapter 不兼容，不能混用。
- 模型覆盖时序定位、空间定位、跟踪等七类任务；仓库公开评测不是 AIC 联合评分器，公开指标不能换算成赛事分数。
- “标注即 rollout”仍然需要标注，不表示自动补齐缺失媒体和坐标映射。
- 作者训练文档说明整理后的训练数据将另行上传，目前未包含在 Git 仓库。现有证据没有提供我们 987 条弱标签对应加工短片的恢复方法。
- Hugging Face 4B 模型 revision：01850297d5ab2adaaf130f700ed7cec52993d956；五个 safetensors 分片，API 报告存储约 10.38 GB。尚未下载并完成离线加载。
- 作者环境为 CUDA 12.9、驱动至少 575.51.03，测试软件含 Transformers 5.5.4、vLLM 0.19.1。当前训练机为 RTX 6000 Ada，驱动 570.144、显存 46068 MiB；检查时占用 176 MiB、磁盘可用 166 GB。不能照搬作者环境或据此保证成功。
- 作者原始 4B 训练报告单卡峰值 50.9 GB，超过当前卡显存；不直接启动原始训练配方。

## 执行决策

1. 加工短片溯源由执行端承担，不要求用户寻找未知文件；现有未验证对应关系的标签暂不用于训练。已下载的源视频仍然可用，缺失的是特定派生标签与媒体的可验证对应关系。
2. 优先验证公开 Video-ORA-4B 成品模型，保持旧模型、adapter 和 43.4800 分提交包可回退。独立环境先解决当前驱动兼容；不升级系统驱动，不修改其他环境。
3. 在有可信标注的开发样本做空间定位、跟踪和时序推理小测试，检查原视频时间、帧号、坐标以及跟踪稳定性；不人工修正测试视频。
4. 固定同一批输入和输出处理，分别对照旧模型与 OraRL：先只更换时序模块，再只更换空间模块，最后组合。定位/跟踪任务必须给出明确目标或定义自动目标选择流程，不能把任务能力列表当成自动裁剪方案。
5. 保存模型版本、配置、输出、耗时、峰值显存和验证失败项。内部指标只用于筛选，不声称等于 AIC 官方分数。
6. 通过格式及边界检查后生成候选包，由用户上传获取官方分数。57 分是目标，当前没有证据保证达到。
7. 只有数据映射、任务目标、训练/验证隔离和收益判断依据明确后，才安排适配训练。重新训练旧 query retrieval LoRA 不是当前优先项。
